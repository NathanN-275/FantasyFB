Neon-specific configuration may exist only inside infrastructure and deployment modules.
Do not call Drizzle directly from UI components.
All database access must pass through documented repository interfaces.
Authentication requirements
Keep authentication behind a narrow AuthProvider interface.
Initially implement GitHub OAuth using Auth.js or Better Auth.
The private version should support an allowlist containing one or more GitHub user IDs.
Do not use display names or GitHub usernames as the permanent authorization identifier . Use the
immutable provider account ID.
The public demo must not require authentication.
The private workspace must require authentication.
Do not expose OAuth client secrets to the browser .
Realtime requirements
Do not require database-level realtime features in version one.
For live Sleeper drafts:
Poll the documented Sleeper draft endpoint.
Normalize new draft picks.
Submit them to the draft event engine.
update the browser state immediately.
Persist the append-only draft event log to PostgreSQL.
Design realtime behavior behind interfaces so WebSockets, Server-Sent Events, polling, or another realtime
service could be added later .
Do not make the domain layer dependent on a particular realtime vendor .
Storage requirements
Keep file and object storage behind a StorageProvider interface.
